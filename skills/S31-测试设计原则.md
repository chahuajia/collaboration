# S31 测试设计原则

## 上下文

写测试时反复遇到"该封装什么、该测什么、怎么组织"的问题。
零散的判断会导致测试腐化。

## 问题

- **冗余断言** —— helper 已保证的事，测试里再断言一遍。
- **Act/Assert 被封装** —— 测试失去"身份"。
- **通用 Arrange 重复** —— 每个文件都写一遍 `setupWorkspace`。
- **单轮复现** —— bug 只写"最小复现"，不写"同类场景"。

## 方案

### 一、What / How 在测试的映射

| 段 | 类型 | 处理 |
| :--- | :--- | :--- |
| **Arrange 通用部分** | How | **封装** |
| **Arrange 特定部分** | What | **保留** |
| **Act** | What | **永不封装** |
| **Assert** | What | **永不封装** |

**"What 不可封装"是它的身份** —— 封装 = 抹掉身份。

### 二、冗余断言的判据

**"如果这条断言挂了，还继续跑后续断言吗？"**

- **"不该继续"** → 它是"前置条件" → helper 已保证 → **删除**。
- **"继续跑"** → 它是"测试意图" → **保留**。

### 三、bug 测试的两类

| 类型 | 验证 |
| :--- | :--- |
| **最小复现** | "bug 真的存在" |
| **同类场景** | "修复是否泛化" |

### 四、通用 Arrange 的封装

```ts
const ctx = useTestWorkspace();
// 一行完成 20 行的 beforeEach/afterEach 注册
```
### 五、具名工厂优于对象参数
```
// 差：读者要"解码"
await writeEntry({ relPath: 'skills/S1.md', id: 'S1', kind: 'skill', collabDir });

// 好：What 显式
await writeSkill('skills/S1.md', 'S1', collabDir);
```
## 反面

- 不要把 Act/Assert 封装成 helper。
    
- 不要保留 helper 已断言的冗余 `expect`。
    
- 不要只写"最小复现"。
    
- 不要用对象参数替代具名工厂（90% 场景）。
