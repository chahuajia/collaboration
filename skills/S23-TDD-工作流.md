# S23 TDD 工作流

## 上下文

需要写可维护、可验证的代码。

## 问题

- 后写测试覆盖不到边界。
- 实现先行容易偏离规格。

## 方案

### 红 → 绿 → 重构

1. **红**：先写测试，跑，看它失败。
2. **绿**：写最简实现让它通过。
3. **重构**：改善实现，测试仍通过。

### 领域层 TDD 的特殊优势

- 领域层是纯函数，**不需要 mock**。
- 最快反馈。
- 从底向上：值对象 → 规则 → 用例 → 集成。

### 顺序

| 顺序 | 写什么 | 反馈速度 |
| :--- | :--- | :--- |
| 1 | 值对象测试 | 最快 |
| 2 | 规则测试 | 快 |
| 3 | 用例测试（fake loader） | 中 |
| 4 | IO 集成测试（临时目录） | 慢 |
| 5 | CLI 端到端测试 | 最慢 |

## 反面

- 不要为无行为的 DTO 写测试。
- 不要在没有失败测试的情况下写实现。
- 不要跳过"红"直接写实现和测试。
