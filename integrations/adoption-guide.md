# 接入与交接指南

## 上下文

`usage-guide.md` 回答**"已经在用的人怎么用"**（该不该查 / 怎么查 / 怎么写条目）。
本文件回答另外两个问题：**"我要不要接"** 和 **"接进来之后怎么交给别人"**。

一句话结论：**能用，但适用范围比你想的窄；收益的形状不是"写得更好"，是"不照着坏代码走"。**

## 问题

- **先搬正文**：默认动作是"把这 126 条搬过去"，而正文换个项目就是噪音，且带着上下文税。
- **先建结构**：目录、模板、CODEOWNERS 都搭好，但**没有一根会亮的线** —— 于是全库变成死文档。
- **交接只交接"是什么"**：新人读到的是 100 多条结论，而不是"哪几条承重、凭什么、哪条已被测试固化"。
- **交接一份会腐烂的 HANDOVER**：实测发生过 —— 交接文档写 HEAD `303dc35`，实际早已前进。

## 方案

### 一、先决定：这个项目该不该接（问 4 个问题）

| 问题 | 该接 | 不该接 |
| :--- | :--- | :--- |
| 会持续多个会话 / 多个 agent 吗？ | 会 | 一次性脚本、玩具项目 |
| 项目里**已有坏模式**会被模仿吗？ | 有旧代码、多域、历史包袱 | 全新绿地、代码基极小 |
| 风险是**数据/契约**类还是样式类？ | 数据正确性、契约漂移、错误映射 | 命名风格、格式偏好 |
| 有人愿意维护**机制**吗？ | 有（哪怕只有你） | 没人接 → 退化成死文档 |

**判据（一句话）**：

> 如果你回答不出"**不读它，模型会照着本地哪个模式做错**"，
> 这个项目就不需要它。答得出来 → 只写那一类，别写别的。

**必须同时接受的三件事**（否则别接）：

1. 收益证据是**拦灾**，不是提速。唯一干净的对照实验测出**零差异**（空项目双臂，读库臂墙钟 +55%）。
2. 有**上下文税**：全量注入 126 条约几万 token。
3. **机制不装就不生效**：校验器、接线、响应协议缺一，收益归零而成本照付。

### 二、30 分钟起步（顺序不能换）

| # | 动作 | 为什么在这个位置 |
| :--- | :--- | :--- |
| 1 | 跑通一个校验器（YAML / id / 链接 / 章节 / 索引，5 条规则就够） | **没有门禁，后面全是散文** |
| 2 | 把它接进 CI 或 pre-push | 没接线的仪器等于没装 |
| 3 | 建**两本空账本**（收益 / 缺口），只要表头 | 格式比内容重要；成对才有方向 |
| 4 | 写 `AGENTS.md` 薄入口 + **3 行**症状表 | 第一路由按"要干什么"组织，不要按条目清单 |
| 5 | 加入库门槛：新条目必须写 `falsifier` | 从第一条起就要求，否则存量 100 条都要补 |
| 6 | 开三条出口：`dormant` / `graduated`(enforced) / `known-gaps` | 缺一条就只增不减 |
| 7 | **最后**才写正文，只写第 1 节判据筛出来的那些 | 顺序反了就会得到一份漂亮的死文档 |

### 三、交给 agent（执行层）

已有的三个资产，**不要重写，直接指过去**：

| 资产 | 作用 |
| :--- | :--- |
| `AGENTS.md` | 自动加载的入口：阅读顺序 + 症状路由表 |
| `integrations/usage-guide.md` | 该不该查（判据表）→ 怎么查（三步）→ 怎么写（三条门槛）→ 三条诚实说明 |
| `collab mcp` | 结构化读取：按 id 读单条、检索、校验、读 catalog —— 不必把全库塞进上下文 |

**交接时先修一件事**：`collab memory` 的过期项。
实测教训：7 个工作记忆文件 **6 个过期 8–9 天**，红灯亮着没人接 ——
新 agent 读到的"当前状态"是错的，而它**看起来像查过了**。

**给新 agent 的第一句话模板**：

> 真相仓是 `<业务仓>`；`<KB 仓>` 只放长期知识；`<工具链>` 提供 validate/catalog/retire/mcp。
> 先读 `AGENTS.md` 的症状表；表里没有就用 catalog 检索；都没有就**报告"找不到"并记 known-gaps**。
> **AI 不 commit、不 push**；「继续」不等于 merge。

### 四、交给维护者（维护层）

交接的不是结论，是**三样能自己亮的东西**：

1. **仪器 + 响应协议**：每台仪器要写清"红灯亮了我做什么"。
   只有两个合法响应：**更新它**，或**降级归档**。"知道了但不动"是它失效的定义。
2. **破坏性变更三件套**：改基座（目录 / kind / id / 字段 / 链接 / 生成物）必须
   **ADR + 迁移脚本 + 校验归零**，缺一不可。实测代价：一天内改四次基座、零迁移脚本。
3. **毕业与退役的判据**：一条规则被写进测试/工具后，条目**退出路由索引**（不是删）。
   知识库的价值里包含"它能收缩"。

## 反面

- **不要**交接 126 条正文。交接**五样**：入口 + 两本账本 + 修剪政策 + 校验器（+ 症状表）。
- **不要**交接没接线的规则 —— 那是负优化：增加协调成本，不改变行为。
- **不要**让新人先读全库 —— 上下文税是真的花掉的。
- **不要**交接"我们的最佳实践"，要交接**判据 + 证据路径**（哪个 commit / 哪个测试）。
- **不要**把项目特有决定包装成通用模式对外推 —— 换个项目就是噪音。
- **不要**在没有基线时开工（派工前置两条：**基线绿 + worktree 重新基线**）。
- **不要**指望它提速。它拦灾。若你要的是"更快写完"，它只会让你更慢 —— 实验已经证明了。
