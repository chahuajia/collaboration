# 修剪策略

## 触发规则

| 触发 | 动作 |
| :--- | :--- |
| 新技能被引用 ≥ 3 次 | 提升为独立文件 |
| 某分支 ≥ 7 个条目 | 建子目录 |
| 两条目重叠 ≥ 50% | 合并 |
| 6 个月未被引用 | 标记 dormant |
| dormant 再 6 个月 | 删除 |
| 结构性决策 | 写 ADR |

## 定期回顾

每月一次：
- 看 evolution-log 最近变更。
- 看 dormant 条目，决定删除或复活。
- 看杠杆节点是否变化。

## 反面

- 不要因为“写了很久”就保留无用条目。
- 不要频繁重构目录结构。
## 社区同步策略

- 主干合并后，fork 通过 `collab sync` 拉取。
- 若某条目被 ≥ 3 个 fork 引用，提升为独立技能。
- 若某条目在主干 dormant 但在 ≥ 1 个 fork active，先讨论再决定。
- 主干定期扫描 fork，吸收高价值条目（见 patterns/horizontal-gene-transfer）。
