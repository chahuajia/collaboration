# ADR-0009 id 是不可变快照

## 背景

约定层收敛（19 → 8）后，`agreements/` 里留下缺口：`A1 A2 A5 A7 A8 A9 A11 A15 A17 A18 A19` 都不在了。

由此产生三个必须回答的问题：

1. 删除/转移条目时，**id 要不要跟着变**（重编号，保持连续）？
2. 整体目录下的文件**要不要一起改**？
3. 编号会越来越大（`S100+`），不利于使用 —— 那能不能重排？

## 决策

**id 是不可变快照。永远不重编号。**

| 问题 | 答案 | 理由 |
| :--- | :--- | :--- |
| 删除后要重编号吗 | **不要** | 缺口就是**死亡记录**。补上缺口等于抹掉"这里曾经死过一条" |
| 转移时要改 id 吗 | **不要** | id 是身份，路径是住所 —— 搬家不改身份证号 |
| 目录下其他文件要改吗 | **不要** | 重编号是**最贵的错误**：ADR、evolution-log、`git log`、外部引用会一起失效 |
| 编号太大怎么办 | **靠语义后缀，不靠重排** | Git 用 40 位哈希、Jira 用 `PROJ-1234` —— 没人因为编号长就重排 |

### 身份与描述的分离

```
S12-边界解析
└─┬─┘ └──┬──┘
  │      └─ 描述：可改（改语义、改措辞）
  └──────── 身份：不可变
```

**编号是身份，语义后缀是描述。** 引用以**编号前缀**为锚，才对得起"id 不可变"。

## 后果

正面：

- 任何历史记录（ADR / 日志 / 对话）**永远引用得到**。
- 改名（语义后缀）不影响身份。

负面：

- `agreements/` 的编号会长期是 `A3 A4 A6 A10 A12 A13 A14 A16` —— **看起来不连续**，
  新读者可能误以为"文件丢了"。需要在 `_index.md` 说明**缺口是刻意的**。

## 替代方案

- **删除后重编号保持连续** —— 否决：见上，代价是全库引用 + 全部历史失效。
- **改用纯语义 id（`boundary-parsing`）** —— 否决：丢掉"口头引用短"和"天然有序"两个好处；
  且纯语义 id 在措辞变化时要整体改名。
- **给编号加前缀字母池扩容（`SA1`）** —— 暂不必要：`S100+` 并不影响使用，只是不好看。

## 补充决策（2026-09-16 晚）：链接锚在 id，`aliases` 负责让它能被解析

**用户实测澄清**：Obsidian 中改名**不会**断链（编辑器会自动改写链接）；
而且最初的意图就是**用 id 作身份、跳转也用 id** —— 只是当时没验证过。

### 那批 id 断链的真正成因

Obsidian 解析双链只有两条路：**文件名** 或 **`aliases` 里的别名**。
所以 `[[S12]]` 能跳，靠的不是"它是 id"，而是"**id 被登记进了 aliases**"。

而全库**没有任何规则要求"id 必须出现在 aliases 里"** —— 谁忘了写，
谁的 id 链接就静默断掉，且 `collab validate` 用 id 也能解析，**查不出来**。

> **不是"id 不能用"，是"id 没有登记成 alias"。缺的是验收，不是能力。**

### 落地的两条规则

| 规则 | 内容 |
| :--- | :--- |
| `ID_NOT_IN_ALIASES` | `frontmatter.id` 必须出现在 `aliases` 里 —— 否则 id 形式的链接在渲染层解析不了 |
| 解析器 | **id 与文件名都认，推荐 id**（不可变快照，改名不失效） |

两条合起来，"校验器的判定"与"渲染器的判定"才来自同一处 ——
`resolvesRef` 的 id 分支之所以成立，**前提由 `idIsAlias` 保证**。

### 为什么不锚文件名（尽管 Obsidian 会自动改写）

Obsidian 改名会自动改写链接，但 **git / CLI / 静态站点不会**。
规则不能建立在"用户恰好在 Obsidian 里改名"这个前提上 ——
锚点必须选在**任何工具里都不变**的那个：**id**。
