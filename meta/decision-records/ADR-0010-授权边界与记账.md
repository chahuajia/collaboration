# ADR-0010 授权边界与记账

## 背景

用户为了提效，提出：**"允许你自动执行全部动作，敏感的通过弹窗让我选择。"**

这个提议里有一个**实测不成立的前提**：

| 期望 | 实测 |
| :--- | :--- |
| 敏感动作能弹窗问用户 | `request_user_input` **只在 Plan 模式可用**；Default 模式下工具不存在 |

**结论先行**：弹窗不是一条可依赖的通道。**如果按"能弹窗"来设计授权，那么在最需要它的场景（Default 模式）里，它一定不存在** —— 于是 agent 要么静默继续，要么卡住。两条都坏。

所以本 ADR 把授权写成分档的**判断规则**，而不是写成"等我的弹窗"。

## 决策

### 一、三档边界

| 档 | 动作 | 授权 | 记账 |
| :--- | :--- | :--- | :--- |
| **A** | 写/改工作区文件、建目录、跑构建与测试、生成产物（`index` / `catalog`）、读任何文件 | **直接做** | 不必逐条记账 |
| **B** | `git add` / `commit` / `amend` / `rm --cached`、删除或移动工作区文件、归档 | **做，但附记账** | **决定 + 为什么 + 撤销命令** |
| **C** | `push`、改 `agreements/` 的语义、加新 kind / 新顶层目录（= 基座破坏性变更）、删知识库条目 | **停下，在回复里问** | 等答复后再做 |

**判据（不是清单）**：

> **动作能不能被"读到它的人"用本地信息撤销？**
> 能 → A/B；不能（外部可见、或改变他人依赖的契约）→ C。

### 二、B 档的记账格式

每次 B 档动作，产出三行，缺一不可：

```
决定：<做了什么>
为什么：<触发它的证据>
撤销：<一条能直接跑的命令>
```

**为什么"撤销"必须是命令**：写"可以回退"是**意图**，写 `git revert 7a51699` 是**能力**。
只有后者能在下一个会话里被执行 —— 而下一个会话没有本次对话的记忆。

### 三、C 档的替代通道（因为弹窗不存在）

弹窗不可用时，C 档 = **把问题留在最终回复里，然后停**。

**不许**：

- 把 C 档混在"顺手做了"里
- 用"用户说过允许全自动"当作 C 档的授权 —— **用户授权的是效率，不是基座风险**
- 为了不打断流程而替用户做 C 档决定，事后再说明

### 四、与既有约定的关系

| 既有 | 本 ADR 的影响 |
| :--- | :--- |
| `A7`（AI 不 push，已在约定层收敛中删除） | **由本 ADR 继承**：push 属 C 档，硬边界 |
| `A21`（决策授权 = 先做 + 记账） | **细化**：把"决策"拆成了 A/B/C 三档，并补上"撤销必须是命令" |
| `meta/base-contract.md` | **不动**。改基座需要 ADR + 迁移脚本 + validate 归零，本 ADR 不豁免自己 |

## 后果

正面：

- **不依赖"弹窗存在"这个假前提** —— 换客户端、换模式都不会让授权逻辑失效。
- B 档的三行记账让"回退能力"**跟着产物走**，而不是跟着对话走。
- C 档有了明确判据（**能不能被本地撤销**），不必每次重新讨论"这算不算敏感"。

负面：

- C 档会**打断流程**，比"先做了再说"慢。
- 判据仍是人（agent）的判断 —— **它可能把 C 判成 B**。
  缓解：C 档清单里那四项（push / 约定语义 / 新 kind / 删条目）是**硬边界**，不走判据、直接停下。

## 替代方案

- **全部动作都做，事后再报告** —— 否决：push 和基座变更**不可本地撤销**，事后报告的代价由用户承担。
- **全部动作都问** —— 否决：把用户重新变成瓶颈，等于放弃 agent 的主要收益（这正是用户要解决的问题）。
- **靠弹窗（`request_user_input`）** —— 否决：**实测在 Default 模式下不可用**，见背景。
- **只列允许/禁止清单，不给判据** —— 否决：清单必然漏项（同 `check-round0.mjs` 前三版的事故），判据才能覆盖没列到的情况。
