# 用互相独立的仪器验证（工具会沉默、会吵、也会坏）

## 上下文

"我做对了吗"这个问题，通常交给工具回答：lint / 类型检查 / 测试 / grep。
但**仪器本身会沉默（该报不报）、会吵（报一堆无关）、也会坏（根本没跑，却返回了像结论的东西）**。
只信一台仪器，等于把错误从"看得见"搬到"看不见"。

## 问题

本会话实测的四种失效，每一种都真实发生过：

1. **沉默（该报不报）**：
   - 改名后**父 barrel 的相对 `export *`** 不在扫描范围内；
   - 相对导入用了**单引号**（`from './x'`），而检查写成双引号 `from "\.` → 漏检；
   - 被搬文件的**同目录邻居**用 `./x` 引用它，而消费者搜索用的是别名路径 → 漏 3 个；
   - 消费者从 **barrel 路径**取用被搬的名字 → 用模块路径搜不到；
   - 运算符只列了 `$in` 而漏 `$nin`（`\$(ne|in)\b` 永远匹配不到它）；
   - 规则只写 `@/x/*`，于是 `import … from "@/x"` 这种**裸导入**完全绕过。
2. **噪音（报了但无关）**：33 条命中里大半是别家同名文件；**注释里写了算子字面量**，让"还剩几处"多出一条假阳性。
3. **仪器坏了 / 根本没跑**：
   - `npx tsc` 因该包没有本地 `typescript` 而**静默未运行**（exit 1，但 0 条 `error TS`）；
   - 同一条命令第二次报 `spawn powershell.exe ENOENT`（**基础设施失败，脚本一行未执行**）；
   - 自写的验证脚本里函数名 `Dir` 撞了 PowerShell 内置别名 → 逻辑从未执行，而它"正常地"输出了我想要的结论。
4. **仪器之间互相遮蔽**：同一 rule key 被多个配置块匹配时，**后匹配者替换前者** → 新规则"绿"了，其实从未生效；
   以及**探针只覆盖了 pattern 的一支写法**，于是"会红"的结论只对那一支成立。

## 方案

1. **每台仪器都要有探针**：先证明"**它会红**"（故意写一个违规 → 必须报错 → 删掉），再相信它的"绿"。
2. **交叉验证用另一类仪器**：门禁说绿时，用 grep / read **再看一遍**（权威实现 vs 配置规则、源码 grep vs lint 各算一台）。
3. **改完用同一把尺子复量**："边被转移"极易被当成"边被消除"（本会话靠逐步复量才把 6 条越界真正降到 0）。
4. **数字与结论一律引用工具输出**，不凭记忆写（本会话我凭记忆写的计数被同一次调用的输出当场反驳）。
5. **输出必须带文件边界**（先 `FILE:`，再该文件的错误行）：否则会**跨文件误归因**，进而错怪规则。
6. **检索键选"唯一且不依赖上下文"的那一层**（例如 basename），**集合类要写全**（运算符、引号形式、子路径与裸路径）。
7. **形状变化要有对照**：pattern 有几支，探针就覆盖几支；规则落位要按"**后匹配者胜**"来设计（窄规则放在宽规则之后，并携带并集）。

## 反面

- 把"**工具说绿**"当成"**做对了**"：假阳性最贵的代价不是烦，而是**让仪器被无视**——一条永远绿（或从不运行）的门禁等于没有门禁。
- 把"**没搜到**"当成"**不存在**"：沉默的成因几乎总是**检索键选错**，而不是事实。
- 在**没有可用仪器**的地方下结论（或为了让它绿而放宽规则）。
- 只测一种写法就宣布"拦住了"。
