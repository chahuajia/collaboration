# 宽容解析：对格式宽容，对语义严格

## 上下文

编写解析外部文本的代码。输入来源不可控：用户粘贴、AI 生成、第三方系统导出。
真实输入往往"看起来对，但格式不标准"。

## 问题

**严格解析会拒绝真实输入，宽容解析会放过错误输入。** 两者都有代价。

典型的严格失败：

- 结束标记的 `=` 数量不一致（A17 文档里就有两处）
- 标记两侧多了空格
- 行尾有不可见字符
- 路径多了 `./` 前缀

如果解析器因为这些拒绝输入，用户看到的是"解析失败"，但**内容本身是完整的**。

## 方案

### 核心原则

**对格式宽容，对语义严格。**

| 维度 | 态度 | 例子 |
| :--- | :--- | :--- |
| 标记的书写形式 | 宽容 | `=+` 不固定数量、两侧空白允许 |
| 路径的写法 | 宽容（由后续 `apply` 规范化） | 保留原样，不在此处规范化 |
| 块的内容 | 严格 | 空块报错、重复路径报错 |
| 块的结构 | 严格 | 未闭合报错 |
| 块外的内容 | **看边界依据**（见下） | 边界自描述 → 跳过 + warn；边界靠包装 → 必须报错 |

### 块外内容：先问"契约知不知道它是不是内容"

分界线不在"宽容 / 严格"，而在**边界依据**：

- **边界靠内容自描述**（条目自带 frontmatter，`id` / `type` 就是边界）：
  块外的开场白、代码围栏、说明表**本来就不是内容** → 跳过。
  但**跳过要配 warn** —— 让人能核对"少的那一段是不是真该在块外"。
- **边界靠人为包装**（成对的 `===== FILE:` 标记）：块外出现非空白文字时，
  契约**无法区分**"粘贴范围错了"还是"这段本就在块外" → 必须报错，不许猜。

判据一句话：**敌人是"静默"，不是"跳过"。** 有依据就跳过 + warn；没依据就报错；两者都不许不出声。

### 实现要点

```ts
// 形式宽容：= 数量不固定、两侧空白允许
const FILE_MARKER = /^=+\s*FILE:\s*(.*?)\s*=+\s*$/;

// 边界自描述 → 块外散文跳过 + warn（ADR-0012）
if (isDocumentStart(lines, i, limit)) { /* 取块，路径由 id + type 派生 */ }

// 边界靠包装 → 块外非空白内容必须报错（不猜）
if (currentPath === null && line.trim().length > 0) {
  issues.push(ParseIssues.invalid(`content outside any block: ${truncate(line)}`));
}
```

**全有或全无**：任何一条不过，返回全部 Issue，一个块都不产出。
不要"尽力解析"——那会让调用方拿到部分结果，误以为全部成功。

### 2026-09-26 的方向修正（[[ADR-0012]]）

这条 pattern 当天是从一个"边界靠 `===== FILE:` 标记"的实现里提炼的；同一天，
对话式 AI 的真实输出（开场白 + 围栏 + 条目 + 协议示例 + 说明表）让旧契约**整单拒收**。

改成"跳过 + warn"的**不是宽容度**，是**边界依据**：从"人写的包装"换成"内容自描述"。
**先说清这个区别** —— 否则下一个人会把结论读成"再放宽一点就行"，继续逐例打补丁。

## 反面

- 不要对语义宽容。空块、重复路径、未闭合块——这些必须报错。
- 不要静默丢弃块外内容（看不到的丢失比报错更危险）—— 但**跳过 ≠ 静默**：跳过必须配 warn。
- 不要在解析层做规范化（如路径转换）。规范化是 `apply` 的职责，解析层只有一份真相。
- 不要"尽力解析"后返回部分结果。调用方无法区分"部分成功"和"全部成功"。
- 不要用严格解析拒绝形式差异。`=` 数量不同不是错误，是真实世界的常态。
- 不要把"边界依据换了"读成"宽容度调大了"——前者治根，后者只会换来下一条补丁。
