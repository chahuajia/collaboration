# 人机协作的层级 Actor 系统
## 上下文
设计"人机协作流程"时，直觉上用"有限状态机（FSM）"建模。
但 FSM 会丢失**并行性、异步性、层级结构** —— 它只能描述"骨架"。
## 问题
- **FSM 假设"全局单一状态"** —— 但人机协作中，人和 AI 各有自己的状态。
- **FSM 是同步的** —— 但实际协作是异步的（你 review 时，AI 可以预写下一个测试）。
- **FSM 是扁平的** —— 但每个状态内部有子状态。
- **纯 FSM 建模** → 丢失关键特性 → 流程设计失真。
## 方案
### 一、三层模型叠加
| 层 | 模型 | 作用 |
| :--- | :--- | :--- |
| **骨架** | **FSM** | 描述"宏观状态与转移" |
| **结构** | **HSM** | 描述"每个状态内部的子状态" |
| **动力学** | **Actor** | 描述"人和 AI 的异步交互" |
**三者缺一不可** —— FSM 给"骨架"、HSM 给"细节"、Actor 给"动力"。
### 二、FSM 骨架（五阶段）
```text
IDLE → SPEC_REVIEW → TEST_REVIEW → IMPL_REVIEW → DONE
         ↑              ↑               ↓
         └──────────────┴───────────────┘
           拒绝 / 新需求 / 回退
```
**每个状态有明确的"进入条件"和"退出条件"**：

|状态|进入条件|退出条件|
|---|---|---|
|**IDLE**|无|需求出现|
|**SPEC_REVIEW**|有需求|规格通过 / 回退|
|**TEST_REVIEW**|规格通过|测试通过 / 回退|
|**IMPL_REVIEW**|测试通过|实现通过 / 回退|
|**DONE**|全部通过|——|

### 三、HSM 子状态（每个状态的内部）

**SPEC_REVIEW 内部**：
DRAFT → DISCUSSION → FINAL
  ↑                    ↓
  └────────────────────┘
    反复修改
**TEST_REVIEW 内部**：
READ_TESTS → CHECK_BOUNDARIES → CONFIRM_COVERAGE → APPROVED
**IMPL_REVIEW 内部**：
READ_IMPL → CHECK_STYLE → CONFIRM_INTENT → APPROVED
**HSM 的价值** —— **用"子状态"精细化描述** —— 而不是"FSM 的单层扁平"。

### 四、Actor 模型（动力学）

**两个 Actor**：

|Actor|内部状态|消息|
|---|---|---|
|**用户**|"理解状态"|需求 / 反馈 / 批准|
|**AI**|"生成状态"|规格 / 测试 / 实现|

**关键特性**：

|特性|描述|例子|
|---|---|---|
|**异步**|Actor 之间消息异步|用户 review 时，AI 可以预写测试|
|**并行**|多个 Actor 可同时处理|用户读规格时，AI 准备测试草稿|
|**独立状态**|每个 Actor 有自己的状态|用户"理解了 A"，AI"生成了 B"|
|**消息驱动**|通过消息转移状态|"规格通过"是一条消息|

### 五、为什么不是纯 FSM

|维度|FSM|HSM + Actor|
|---|---|---|
|**状态**|全局单一|每个 Actor 独立|
|**时序**|同步转移|**异步消息**|
|**并发**|无|**可并行**|
|**层级**|扁平|**层级**|
|**延迟**|瞬时|**需要时间**|

**纯 FSM 建模的失真**：

- **"用户 review" 和 "AI 生成" 被当成"同一时刻"** —— 实际**异步**。
    
- **"规格阶段"被当成"一个状态"** —— 实际内部有**子状态**。
    
- **"用户理解" 和 "AI 输出" 被耦合** —— 实际**独立**。
    

### 六、准确表述

> **"人机协作是一个带反馈环的层级 Actor 系统。  
> 可以投影为有限状态机来理解骨架，  
> 但用 FSM 建模会丢失并行性和异步性。"**

**FSM 是分析工具，不是实现方式。**

- **用它理解结构** —— 可以。
    
- **用它固化流程** —— 会丢关键特性。
    

### 七、与 A10 的关联

**A10 的"五阶段"** —— 是本 pattern 的**FSM 骨架**。

**A10 的"回退"** —— 是 FSM 的**转移**。

**A10 的"Review 上移"** —— 是 HSM 的**子状态切换**（从"看实现"到"看规格"）。

**A10 未明说的**：

- **Actor 模型** —— 用户和 AI 的异步。
    
- **并行性** —— 你 review 时 AI 可以预写。
    
- **独立状态** —— 用户的理解 ≠ AI 的输出。
    

**本 pattern 是 A10 的"完整模型"**。

## 反面

- **不要**把 FSM 当作"流程的最终形态"。
    
- **不要**假设"用户和 AI 同步"。
    
- **不要**让"流程"僵化 —— 它是"骨架"。
    
- **不要**忽略"子状态" —— 每个阶段的内部复杂。
