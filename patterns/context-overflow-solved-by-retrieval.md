# 上下文溢出用检索

## 上下文

AI 或系统的"知识库"越来越大，担心"上下文放不下"。

## 问题

- 直觉解法是"把上下文寄放到知识库里"。
- 但寄放会让知识库变重——每次都要读取。
- 而且**分不清哪些该寄放、哪些不该**。

## 方案

### 核心原则

**知识库不是"上下文"——它是"按需检索的外部记忆"。**

**溢出的解法是"更好的检索"，不是"更多的寄放"。**

### 三层分工

| 层 | 承载 | 生命周期 |
| :--- | :--- | :--- |
| **工作记忆**（单次对话上下文） | 当前任务的临时状态 | 秒级 - 分钟级 |
| **进度文档**（如 `working-memory/`） | 跨对话的工作状态 | 天级 - 周级 |
| **长期知识**（COLLABORATION） | 提炼后的知识条目 | 月级 - 年级 |

### 溢出的真正解法

| 场景 | 错误解法 | 正确解法 |
| :--- | :--- | :--- |
| 条目太多，找不到 | 寄放更多 | 优化 `_index.md` + 双向链接 |
| 单次对话太长 | 寄放上下文 | 分出"进度文档" |
| 知识太分散 | 合并条目 | 建立检索层（未来：图/向量检索） |

## 反面

- 不要把所有内容都"入库"——**大部分上下文是临时的，不值得保存**。
- 不要为了"不丢失"而保存一切——**熵增**比**信息丢失**更糟。
- 不要把"寄放上下文"当成"上下文管理"——它们是两个不同的问题。
