# 层 ≠ 上下文

## 上下文

讨论"模块关系"时，容易把"层"和"限界上下文"混用。

## 问题

- **层**是上下文内部的**结构位置** —— 如 domain / application / infrastructure。
- **上下文**是**领域边界** —— 有自己的模型和语言。
- **两者嵌套**：上下文内部有层，层不是上下文。

## 方案

### 一、判据："它们共享统一语言吗？"

- **共享** → **同一上下文的层**。
- **不共享** → **不同的上下文**。

### 二、层间关系用"内外 + 依赖方向"

**A18 的规则**：

- 用**内层 / 外层**，不用"上下"。
- **外层依赖内层**。

### 三、上下文映射用"7 种模式"

**跨上下文用**：

- **合作关系** / **共享内核** / **客户-供应商** / **遵奉者** / **防腐层** / **开放主机服务** / **另谋他路**。

### 四、"架构层平级" ≠ "领域层平级"

**同一关系，两维答案**：

| 维度 | scripts vs 生产 |
| :--- | :--- |
| **架构层** | 平级（都是外层） |
| **领域层** | 核心 / 支撑（不是平级） |

**判据**：

1. **架构层**：谁依赖谁？
2. **领域层**：谁是核心？谁是支撑？

### 五、嵌套结构
系统  
├── 上下文 A  
│ ├── 层 1  
│ ├── 层 2  
├── 上下文 B  
│ ├── 层 1
**"上下文"和"层"是嵌套的** —— **不是并列的**。
## 反面
- 不要把"层"当"上下文"（不能套上下文映射）。
- 不要把"上下文"当"层"（不能用内外描述）。
- 不要假设"架构层平级 = 领域层平级"。
