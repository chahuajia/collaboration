# W12 条目合并工作流

## 上下文

两条以上条目重叠 ≥ 50%（或明确讲同一件事），需要合并而不留下死链与双真相源。

## 问题

- 合并时只改"主文件"，漏改裸引用 / 模板 / 索引 → 静默死链。
- 保留了冷门 id、删了被引用最多的 id → 改动面爆炸。
- 以为写进 `aliases` 就能解析旧 id → **不能**（解析看 id 与文件名，不靠 aliases 自动转向）。

## 方案

顺序不能换 —— 第 2 步是保险，第 8 步是验收：

1. **读全文**，列出**逐字重复的段落**（这是"该合并"的证据，不是印象）。
2. **`rg` 数引用面**：`[[长名]]` / `[[短 id]]` / **裸引用**（如 `applies-to: [W8]`）/ 模板 / 索引（漏一处就死链）。
3. **写合并条目**，**保留被引用最多的那个 id 与文件名**。
4. **删掉其余文件**。
5. **改引用**：>10 处 → 用一次性 Node 脚本（[[S29]] / [[S30]]），脚本用完即删。
6. **人工改入口与索引**（`AGENTS.md` / `README.md` / `_index.md` 的表格外内容）。
7. **去重**：合并会让 `[[A10]] [[W8]]` 变成 `[[A10]] [[A10]]`，要专门清一遍。
8. **`collab validate`** —— **死链 0** 就是本次改动的验收标准。
9. **写 ADR + `evolution-log`**（约定级必写 ADR）。
10. **更新工作记忆**。

## 反面

- 不要指望 `aliases` 自动接住旧编号 —— 引用必须真改。
- 不要先删再数引用 —— 证据会一起消失。
- 不要在未跑 validate 前宣称合并完成。
