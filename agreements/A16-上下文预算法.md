# A16 上下文预算法

## 上下文

上下文窗口有限且**先进先出**——早期内容会被截断。多数人把上下文当"无限容器"，导致关键约束丢失。

## 问题

- 长对话中，第 1 轮的关键约束在第 50 轮已被截断。
- 一段对话塞多个话题，AI 每次要重新定位。
- 上下文填满后，AI 输出质量下降，但用户以为"AI 变笨"。

## 方案

### 核心原则

**上下文是预算，不是容器。**

### 三项纪律

| 纪律 | 说明 |
| :--- | :--- |
| **入场计算** | 对话开始前问："这次需要读几个文件？多少行？" |
| **优先删减** | 只给"当下需要"，不给"以后可能要" |
| **分段花费** | 大任务切成 5-10 轮对话，每段独立预算 |

### 锚点机制

**关键信息必须重复出现——因为会被截断。**

- 每 10 轮复述一次核心约束。
- 最关键的 3-5 条约束写进 `working-memory/tasks/<task>/anchors.md`，**每次新对话必读**。
- 前情提要由 AI 在复杂回答前复述："当前任务的三个关键约束是 X、Y、Z"。

### 会话切片

一段复杂对话**应该有开场和收尾**。

**开场**：

```text
目标：[本次要解决的问题]
边界：[不讨论什么]
上下文：[需要的文件，一次性给]

```

**收尾**：
```
产出：[本次的条目/决策/待办]
下次：[从哪一步继续]
```

### 反模式

|反模式|症状|对策|
|---|---|---|
|长对话不切|一段 200 轮|每 30-50 轮切换|
|一次多个主题|话题跳跃|Parking Lot 暂存|
|靠记忆不靠文件|决策只在对话里|写进 working-memory|
|上下文填满|每轮粘贴大量内容|按需读取|
|不做收尾|讨论完没产出|显式收尾|
|不复述约束|AI 忘了第 1 轮要求|锚点机制|

## 反面

- 不要把"上下文长"当成"信息全"——它会截断，且**截断是机械的，不按重要性**。
    
- 不要指望 AI 记住所有内容——**记住是例外，遗忘是常态**。
    
- 不要在超长对话里继续推进——**先切分，再继续**。
