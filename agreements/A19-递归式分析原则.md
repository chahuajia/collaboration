# A19 递归式分析原则

## 上下文

分析问题和总结知识时，直觉做法是"看当前问题 → 给结论"。
但"当前问题"往往只是"现象的浅层" —— 真正的本质在"全局上下文"和"多轮迭代"里。

## 问题

- **只盯当前上下文** —— 忽略历史脉络，看不见"这个问题为什么现在出现"。
- **第一轮就给结论** —— 结论停在浅层，没触及本质。
- **分析与沉淀分离** —— 讨论完就完，知识不落地。
- **沉淀不复用** —— 下次分析从零开始。

## 方案

### 一、六层结构

| 层 | 名称 | 含义 |
| :--- | :--- | :--- |
| **L1** | 全局上下文 | 结合**之前很长一段**的对话与条目 |
| **L2** | 深层分析 | **从现象看本质** |
| **L3** | 多角度 | **从局部到全局**、**从孤到整体** |
| **L4** | **递归** | **第一轮结果 → 再分析 → 再返回**（可多轮） |
| **L5** | 落地 | 结果写入 COLLABORATION |
| **L6** | 复用 | 后续分析**从它开始** |

### 二、递归是核心

**"递归"的含义**：

> 每一轮的"结论"，**不是终点** —— 是**下一轮的"输入"**。
> 通过多轮迭代，把"表面问题"转化为"深层问题"，把"具体现象"化为"抽象方法"。

**递归的收敛判据**：

- **当"下一轮的分析"不再产出新洞见** —— 收敛。
- **当"发现的问题"变成"已有条目的重复"** —— 收敛。
- **通常 2-3 轮**。

**递归的最深产出**：

- **不是"某个具体结论"** —— 是**"一个方法论"**。
- **例**：以 A18 为例——
  - 第 1 轮：A18 修正版
  - 第 2 轮：A18 与已有条目的关系 → 发现冲突
  - 第 3 轮：**为什么有冲突？** → 发现"写 A18 时没做全局扫描" → **落到"递归式分析"**

### 三、全局上下文的扫描范围

**"结合之前很长的上下文"具体包括**：

1. **当前对话历史**（至少最近 20 轮）。
2. **相关 COLLABORATION 条目**（写入前扫一遍）。
3. **working-memory**（当前任务状态）。
4. **decisions.md**（历史决策）。

**扫描的动作**：

- **grep** 关键词，找"可能相关"的条目。
- **读** 其中 3-5 个最相关的。
- **比对** 新的想法与已有的是否冲突/互补/重复。

### 四、落地与复用

**落地**：

- **每轮讨论结束** —— 至少**沉淀一个条目**。
- **不落地的分析** = 白分析。

**复用**：

- **新分析开始** —— **先读**相关条目。
- **新条目写入** —— **先查**是否与已有冲突。
- **改条目** —— **先扫**所有引用它的地方。

### 五、检查清单

**每次复杂分析后，问自己**：

- [ ] **我结合了多长的上下文？**（至少最近 20 轮）
- [ ] **我做了几轮递归？**（至少 2 轮）
- [ ] **我扫描了多少相关条目？**（至少 3 个）
- [ ] **我的结论落到了哪些条目？**（至少 1 个）
- [ ] **未来谁会复用这个结论？**（能说出 1 个场景）

**如果任一答不上来** —— **分析不完整**。

### 六、递归是有终点的，但终点是"稳定点"

**核心洞见**：**分析不是"一轮到底"，是"多轮收敛"** —— **收敛的判据不是"找到答案"，是"下一轮不再有新发现"**。

**"单轮" vs "递归"**：

| 单轮 | 递归 |
| :--- | :--- |
| 第一轮给结论 | 第一轮作为输入 |
| 停在"看起来对" | 逼向"看起来对但可能更深" |
| 产出"具体答案" | 产出"方法论" |

**为什么"递归"能触及本质**：

- **第一轮**：看见"现象"。
- **第二轮**：问"这个现象和已知的关系"。
- **第三轮**：问"为什么之前没看到这层关系"。
- **收敛**：**"没看到"的原因是"方法论缺失"**。

**三步把"具体 bug"变成"元规则"** —— **这是"递归"最深的价值**。

**类比**：**考古钻探** ——

- **第一钻**：找到陶片。
- **第二钻**：判断陶片属于哪个朝代。
- **第三钻**：发现整个地层是同一朝代。
- **收敛**：**"这里有一个未被记录的遗址"**。

**每一钻的意义不在"钻本身"** —— **在"它让下一钻问更好的问题"**。

**工作流上**：**递归的节奏**：

1. **第一轮**：**给出"能说得通"的答案**。
2. **第二轮**：**扫全局 + 找冲突**。
3. **第三轮**：**问"为什么之前没扫到"**。
4. **收敛**：**把"为什么"落成方法论**。

**不收敛的迹象**：**每轮都在"表面打转"** —— **没深入到"方法论"**。
### L1 深度和 L4 轮数都按任务动态决定

**原 A19 里 L1 写"最近 20 轮"、L4 写"至少两轮"** —— **都是固定值** —— **这也是"为运行而运行"**。

**修正**：

#### L1 深度判据

| 任务类型 | 深度 |
| :--- | :--- |
| **单点修复** | 当前文件 + 上下文 3 轮 |
| **局部重构** | 相关模块 + 上下文 10 轮 |
| **跨文件重构** | 所有相关条目 + 上下文 20-30 轮 |
| **架构决策** | 全项目 + 所有相关讨论 |

**判断方法**：

1. 本次改动会触及几层？
2. 会触及几条已有约定？
3. 未来会被引用吗？

**≥ 2 个"是"** → 取最大深度。

#### L4 轮数判据

| 任务类型 | 轮数 |
| :--- | :--- |
| **单点分析** | 1-2 轮 |
| **跨文件分析** | 2-3 轮 |
| **架构决策** | 3-5 轮 |

**收敛判据**（每轮结束问）：

1. **本轮是否发现"上一轮没看到的"？** —— 有 → 继续。
2. **本轮的结论和上一轮是否等价？** —— 等价 → 收敛。
3. **本轮的分析是否进入"元层面"（方法论）？** —— 是 → 收敛。

**"为运行而运行"是反模式** —— 递归的目标是"更深"，不是"更多"。
## 反面

- 不要"看当前问题，给结论" —— 这是浅层分析。
- 不要"第一轮就结束" —— 递归至少两轮。
- 不要"讨论完就完" —— 落地是分析的组成部分。
- 不要"沉淀不复用" —— 复用才是沉淀的目的。
