# A13 AI 入口文件规范

## 上下文

AI 进入项目时缺一个"去哪找知识"的入口——没有它，AI 要么盲目扫描，要么依赖用户反复解释。

## 问题

- 每次新对话是白纸，AI 不知道项目当前的焦点。
- 用户默默承担"告诉 AI 读什么"的负担。
- 没有入口，working-memory 和 COLLABORATION 都是"埋藏的宝藏"。

## 方案

### 单一入口：`AGENTS.md`

- **位置**：项目根目录。
- **命名**：`AGENTS.md`（跨工具通用，不锁厂商）。
- **长度**：**越薄越好 —— 只放路由与协议，不放内容**。（**不写死行数**：那是手写计数，必然腐烂；
  真正的不变量是"入口里没有可以被条目替代的内容"。）
- **内容**：
  1. 项目一句话定位
  2. 阅读顺序（working-memory → COLLABORATION → 按需）
  3. 协作规则摘要（只列标题，不复制内容）
  4. 当前活跃任务指向
  5. 更新规则（本文件很少更新）
  6. **工具与接线**（2026-10-06 补）：点名**用什么工具**（CLI / 门禁命令 / 关键仪器），
     并写清**什么时候跑它**。见下「入口必须点名工具」。

### 入口必须点名工具（2026-10-06 补）

**"入口只写'读什么'、不写'用什么工具'，等于这条规范不存在。"**

实测（某新项目，2026-10-06）：agent 通读了入口，整段会话 `collab` 用了 **0 次** ——
判据全写进 `working-memory/`（下一个人读不到），`catalog.json` 停在几行，知识库一次没增长。
它读到的入口里**一个字都没提 CLI**，于是把"知识库"理解成"一堆可以读、也可以手改的 md"。

同一次还暴露两处漏接：入口只路由到 `meta/known-gaps.md`（**收益账本 `interceptions.md` 一次没提**），
于是修剪没有依据（说不清哪条该走）；以及"生成物陈旧"没有响应动作。

**所以入口至少要写三样**：① 工具叫什么（装/跑的命令）；② 每类动作对应哪条命令；
③ **红线出现后的两个合法动作**（更新它 / 降级归档）。详见 [[cli-agent-boundaries]] 与 `AGENTS.md` 的「协议」节。

### 入口有四种载体，更新延迟不同（2026-10-06 补）

> 问题来源：改了 KB 之后，**怎么让新项目 / 其他 agent 及时知道？**

| 载体 | 谁读它 | 更新延迟 |
| :--- | :--- | :--- |
| **KB 本体**（真相源） | 有文件权限的 agent；MCP | **0** —— 谁读谁新 |
| **项目侧 `AGENTS.md`** | 进这个项目的第一读者 | ⚠️ 它是**副本**，会漂移 → 所以**只留指针 + 一条命令**，不复制内容 |
| **MCP** | 支持 MCP 的客户端 | **0** —— 连的是活库，不是快照 |
| **对外文章**（掘金 / 博客） | 人 | ❌ 快照，只能人工同步 → 所以文中必须写"**仓里那份是源头**" |

**结论**：要"及时"，就别复制 —— 让每个入口都**指向** KB，并给它**一条命令**验证那个指向还活着：
**`collab doctor`**（2026-10-06 已实现）—— 它查工作区能否定位 / 校验过不过 / 生成物新不新 /
**入口有没有点名工具** / 有没有 `.git`。**"接错线"从此是一行能红的检查，不是一句叮嘱。**
项目侧那张命令表是**最贵的副本**：今天实测，某项目 `AGENTS.md` 里的表比 KB 落后一整天，
而它引用的还是**已发布文章**里的旧说法（"MCP 只有 6 个只读工具"）。

### 核心原则

**入口指向，不复制。**

- 它告诉 AI"读什么"，不告诉 AI"内容是什么"。
- 内容永远在 COLLABORATION / working-memory 里——单一真相源。
- 入口越薄越好——它是**导航仪**，不是**说明书**。

### 多工具演化

| 场景 | 处理 |
| :--- | :--- |
| 只有一个 `AGENTS.md` | ✅ 单一真相源 |
| 某工具需要专属文件（`.cursorrules`、`CLAUDE.md`） | 作为**局部补充**，写"详见 `AGENTS.md`"，不复制内容 |
| 局部与全局冲突 | **局部优先**——局部知道更多上下文 |
| 局部文件内容 | 只写"局部差异"，不重述全局 |
### 外部知识库：只声明"在哪"，不声明"怎么读"

当 COLLABORATION 不在项目仓库内时，`AGENTS.md` 必须声明**它的地址**。

但**"怎么读"取决于环境，不属于本层**：

| 环境 | 读取方式 |
| :--- | :--- |
| 有文件权限的 agent | 直接读（`--dir` / 路径） |
| 无文件权限的对话式 AI | 由用户按需粘贴 —— 见 [[chatgpt-paste-protocol]] |

**为什么拆开**：入口规范回答的是"知识该从哪里被找到"（跨环境不变）；
而"用什么通道把知识送进上下文"是**环境适配**，换个客户端整条作废。

## 反面

- 不要在入口里复制 COLLABORATION 内容——会产生两个真相源。
- 不要为每个 AI 工具各写一份完整入口——会打架。
- **不要让入口变厚** —— 它一变成说明书，就和真相源两份漂移；要长内容就写条目，入口只留指针。
  （但**别用行数当判据**：2026-10-06 实测，行数上限被手写过、也被改错过 4 次。）
- **不要只写"读什么"而不写"用什么工具"** —— 不知道有工具，等于没有这条规范（见上）。
- 不要忘记在入口里指向 working-memory——那是最重要的跨对话上下文。
