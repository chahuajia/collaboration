## 上下文

DDD 的战略设计强调"统一语言"。方位词（上/下、内/外）是最基础的术语——
若它们的隐喻与真相不一致，读者会在错误的模型上推理。

## 问题

- **"上/下"** 暗示"高层抽象、底层基础" —— 与架构真相相反。
- **"层"与"适配器"** 被混用 —— 前者是节点集合，后者是节点扮演的角色。
- **同一概念多个表述** —— 术语漂移 → 模型漂移 → 架构腐化。

## 方案

### 一、术语规范

| 概念 | 用 | 禁用 |
| :--- | :--- | :--- |
| 架构位置 | **内 / 外** | 上 / 下、高 / 低 |
| 依赖方向 | **外层依赖内层** | 上层依赖下层 |
| 抽象层次 | **前移 / 后置**、**前置 / 后置** | ❌ 上移 / 下移 |
| 变化频率 | **稳定 / 易变** | 高级 / 低级 |
| 节点集合 | **层** | 与"角色"混用 |
| 节点角色 | **适配器 / 设施** | 与"层"混用 |

### 二、"内外"是相对关系

**原则**：**A 依赖 B ⇒ A 相对 B 是外层。**

- **内/外不是绝对位置** —— 是依赖方向的投影。
- **同一实体相对不同实体** —— 可以是内也可以是外。
- **一个实体可以在多条依赖链上同时是"内层"和"外层"** —— 见下方"多层内/外"。

**唯一的绝对**：

> **领域层是最内层，没有例外。**
> 所有其他实体，相对领域层都是外层。

### 三、"层"和"角色"的区分

| 概念 | 类型 | 说明 |
| :--- | :--- | :--- |
| **层** | 节点集合 | 内层、外层（= 内区域 / 外区域的节点集合） |
| **适配器** | 角色 | 外层的一种实现类型 |
| **设施** | 角色 | 外层的另一种实现类型 |

**关系**：

- 适配器**属于**外层，但外层**不都是**适配器。
- 不说"适配器层" —— 说"适配器"或"外层"。

### 四、"内外"是多维分类的一个维度

**"内外"只是描述一个实体的"相对位置"** —— **不是唯一维度**。

参考 [[patterns/faceted-classification]]：

| 维度 | 例子 |
| :--- | :--- |
| **相对位置** | 内 / 外（相对谁） |
| **角色** | 适配器 / 设施 |
| **变化频率** | 稳定 / 易变 |
| **表达风格** | 声明式 / 命令式 |

**同一个实体** —— **在 4 个维度上各有坐标**。

### 五、判据

**判断"内还是外"**：

1. **它依赖谁？** 被依赖的是内层。
2. **谁依赖它？** 依赖它的是外层。
3. **相对谁？** 内外必须"相对谁"才成立。

**判断"适配器还是设施"**：

- **适配器**：把外部世界翻译成内部语言。
- **设施**：提供技术能力。

### 六、本项目术语统一表

| 中文 | 英文 | 备注 |
| :--- | :--- | :--- |
| 条目 | entry | 统一用英文 |
| 规则 | rule | 统一用英文 |
| 值对象 | value object | 统一用英文 |
| 内 / 外 | inner / outer | 关系，是"相对谁"的 |
| 前移 / 后置 | shift-earlier / shift-later | 抽象层次，替代"上移/下移" |

## 反面

- 不要混用"上下"和"内外"。
- 不要把"适配器"当成层级。
- 不要假设"内外"是绝对位置。
- 不要"一会红色一会 red" —— 术语漂移是模型腐化的前兆。
