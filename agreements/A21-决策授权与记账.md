# A21 决策授权：先做，然后记账

## 上下文

复杂任务里，AI 会反复停下来问"选 A 还是 B"。
每个问题都是一个**回合** —— 而在长任务里，**回合是最贵的资源**。

## 问题

- **等批复**：6 个决策点可以挂一整个会话（实测）。
- **静默自己拍**：用户事后才发现，且不知道理由（实测：`apply` 的 4 个未决问题）。
- 两者同源：**"授权形态"没有被定义过**。

## 方案

**把"决策"与"动作"分开 —— 授权只管前者。**

| 类型 | 例子 | 谁来 |
| :--- | :--- | :--- |
| **可逆 + 可验证** | 写代码、加测试、建文件、改注释 | **默认就是 AI** |
| **可逆 + 判断类** | 选目录布局、砍条目、定默认值、挑措辞 | **授权范围内：先做，记账** |
| **要动规则 / 要动别人** | `commit` · `push` · 改约定 · 加新 kind | **不在授权内 —— 需要人** |

### 记账三件套（缺一不算授权）

每做一个判断类决定，交付里必须能回答：

1. **我决定了什么**
2. **为什么**（判据，不是"推荐"）
3. **怎么撤销**（一步能回退吗）

### 授权的失效条件（命中任一条 → 停下来问）

- 决定**不可逆**
- 决定**改变范围**（不只是"怎么做"，而是"做什么"）
- **说不出判据** —— 那说明没想透，先想，别先做

## 反面

- 不要把"授权"读成"可以静默"：**它换的是"不等批复"，不是"不记账"**。
- 不要把**动作**（commit / push / 改约定）也自己做了 —— 那是**改规则**，不是做决定。
- 不要用授权跳过规格：`A10` 的"先给规格"**本身就是减少决策次数的机制**。
- 不要因为"可以自己定"就**降低验证强度** —— 授权加的是速度，不是信心。
